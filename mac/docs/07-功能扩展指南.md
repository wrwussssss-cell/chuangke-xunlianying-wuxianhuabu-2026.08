# 功能扩展指南（二次开发实操手册）

> 按"想加什么"组织，每节给出**改动点清单（文件+函数+行号）**和注意事项。
> 通用建议：后端加功能 = 在 `main.py` 对应分区加函数 + 路由；前端 = 复用现有面板/弹窗模式；文案走 i18n；新字段一律做归一化兼容。

---

## 1. 新增一个"生成渠道"（Provider）——最常见的扩展

以加一个"XX云"生图渠道为例：

1. **默认配置**：在 `default_api_providers()`（main.py:784）加一条默认 provider（id/name/base_url/protocol）。
2. **协议判定**：若上游不是标准 OpenAI 协议，加 `is_xx_provider(provider)`（参考 `is_yuli_provider` main.py:5291 的写法），并在 `provider_protocol`（main.py:4288）/`effective_protocol`（main.py:4318）登记协议名。
3. **生图实现**：写 `generate_xx_provider_image(prompt, size, model, reference_images, provider)`（参考最简实现 `generate_modelscope_provider_image` main.py:9698 或 Gemini 的 main.py:9791），然后在**总调度器** `generate_ai_image`（main.py:11005）里加分支。
4. **异步任务**（若上游是提交+轮询）：实现任务提交/查询；复用 `wait_for_image_task`（main.py:6318）与 `extract_task_id`（main.py:3942）；前端不用改（`/api/image-task-query` 通用轮询）。
5. **生视频**（可选）：在 `canvas_video`（main.py:15046）加分支，参考 `generate_tudou_video`（main.py:14852）。
6. **友好报错**：在 `friendly_image_error_detail`（main.py:9582）/`friendly_video_error_detail`（main.py:9677）加错误翻译。
7. **Key 管理**：无需写代码——Key 自动按 `API_PROVIDER_<ID>_KEY` 存取（main.py:702）。
8. **前端**：`api-settings.js` 大多是协议驱动的，确认新协议在下拉列表（协议常量表）里；若需要特殊表单，参考火山引擎（AK/SK）区块的写法。
9. **验证**：`test_provider_connection`（main.py:13307）按协议探测，为新协议补一个探测分支（参考 `probe_volcengine_auto_detect` main.py:13236）。

## 2. 新增一种画布节点（无限画布）

1. `createNodeByType(type, point)`（canvas.js:3574）加分支：构造默认节点对象。
2. `renderNode(node)`（canvas.js:6090）加渲染分支（DOM 模板字符串 + 事件绑定）。
3. 新建菜单：`openCreateMenu`（canvas.js:3187）加菜单项（含 i18n key）。
4. 序列化：画布 JSON 全量保存节点对象，注意把运行态字段放 `_` 前缀或保存前剔除。
5. 若节点可参与生成：在 `runCanvasGenerate`（canvas.js:11724）里处理，或作为上游被连线（参考 `connectSelectionToGenerator` canvas.js:13547 的 kind 参数）。
6. 智能画布同理：节点分发/渲染在 smart-canvas.js（类型见 05 §1.2），级联行为挂在 `runCascadeStepIntoNode`（smart-canvas.js:14669）。

## 3. 新增一个后端 HTTP 接口

1. 在 main.py 对应业务分区加 `@app.post("/api/xxx")`（FastAPI 自动注册，无需集中注册表）。
2. 请求体建 Pydantic 模型（集中放在 main.py:2437–2860 的模型区）。
3. 返回统一用 dict / JSONResponse；错误 `raise HTTPException`，用户可读信息走 friendly_* 系列。
4. 若接口耗时：仿照 `create_canvas_image_task`（main.py:13961）——`POST` 返回 task_id + 后台线程执行 + `GET /{task_id}` 轮询。
5. 文档：接口加进 `docs/03-后端API接口清单.md`。

## 4. 新增生图参数（如新的风格滑杆）

推荐走**动态参数**而不是硬编码：

1. 后端 `build_image_param_fields(engine, provider, model)`（main.py:14054）为该渠道/模型返回字段定义（类型 number/boolean/text、默认值、选项）。
2. 前端参数面板按 `/api/image-params` 自动渲染（画布与智能画布共用逻辑）。
3. 值随节点保存（画布 JSON 的节点字段），后端实现里从请求体读。
4. ComfyUI 工作流参数则用 `WorkflowConfig`（main.py:18288）机制：在 config JSON 里声明字段，`generate()` 按映射注入。

## 5. 新增一个页面

1. `static/` 下新建 `xxx.html`（复制 `canvas-list.html` 的头结构：vendor 引入、i18n、theme）。
2. JS/CSS 放 `static/js/`、`static/css/`。
3. **无需在后端注册**——静态目录自动服务；若要"首页可见"，在 `index.html` 加入口卡片。
4. 页面标题/缓存版本由 `static_html_response`（main.py:1621）统一处理；如果页面不在它的白名单里，检查 `versioned_static_html`（main.py:1572）的清单。
5. 多语言：文案抽成 key 放 `i18n-core.js`。

## 6. 多语言 / 主题 / 图标

- 新文案：`static/js/i18n-core.js` 加中英两份 key；页面里 `tr('xxx')`（canvas.js:3）。
- 主题色：`static/css/theme.css` + `theme.js`（变量驱动）。
- 图标：lucide 图标名，`renderCanvasIcon(icon, size)`（canvas.js:531）或 `refreshIcons()`。

## 7. 修改 ComfyUI 工作流

1. 在 ComfyUI 里导出 **API 格式** JSON，放进 `workflows/`。
2. 两种接法：
   - **硬编码注入**（内置工作流风格）：在 `generate()`（main.py:18049）里按节点 id 注入 prompt/宽高/种子（注意保持原规则：23=文本、144=宽高、种子节点列表）。
   - **配置化**：写同名 `.config.json`（`WorkflowConfig` main.py:18288），用 `runninghub_collect_workflow_fields`（main.py:18683）同类逻辑从 JSON 抽字段，声明可调参数。
3. 前端 `comfyui-settings.html` 可视化管理（上传/字段配置）。
4. 验证：`POST /api/workflows/{name}/run` + `/api/queue_status` 看队列。

## 10. 自更新清单维护

新增**顶层**文件/目录（例如新的 `mylib/`）后，必须让它能被更新到：
- `github_update_file_list`（main.py:2134）/ `modelscope_update_file_list`（main.py:1993）里加清单；
- `update_allowed_file`（main.py:1924）白名单确认；
- 否则用户"检查更新"后新功能文件不会被下载。

## 11. 调试技巧

- 后端日志：uvicorn 控制台（轮询接口已静音，`QuietAccessLogFilter` main.py:51）；`log_net_error`（main.py:3555）会打印网络错误上下文。
- 看任务卡住：`/api/queue_status`、`/ws/stats`、历史记录里的 `task_id/request_id`。
- 前端断点：直接在 DevTools Sources 找函数（本档所有行号即 canvas.js/smart-canvas.js 行号）。
- 数据坏了：所有 JSON 都有 `normalize_*` 兜底，先看控制台报错里是哪个 normalize 函数抛的。
